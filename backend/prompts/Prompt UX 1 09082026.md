# Mission — Repenser l’UX pour mieux valoriser les contenus à forte valeur

## Contexte

Je souhaite revoir l’UX de l’application afin de mieux mettre en avant les contenus et fonctionnalités qui ont le plus de valeur pour les utilisateurs.

Aujourd’hui, certains éléments importants semblent manquer de visibilité, notamment :

* les **corrigés accessibles gratuitement / en libre accès** ;
* les **contenus récemment ajoutés** ;
* les nouveautés et mises à jour ;
* les contenus populaires ou particulièrement utiles ;
* les fonctionnalités qui méritent davantage d’être découvertes.

L’objectif n’est **pas simplement de rendre l’interface plus jolie**, mais de réfléchir à une UX plus claire, plus engageante et plus efficace.

---

# Ton rôle

Agis comme un **Senior Product Designer / UX Designer + Product Manager**, avec une forte sensibilité :

* UX/UI ;
* architecture de l’information ;
* découvrabilité des contenus ;
* conversion et engagement ;
* hiérarchisation de l’information ;
* design mobile-first ;
* accessibilité ;
* cohérence avec le design system existant.

Tu dois d’abord **comprendre l’application existante avant de modifier quoi que ce soit**.

---

# Étape 1 — Audit de l’existant

Explore le projet et identifie notamment :

* la structure actuelle de l’application ;
* les principales pages et parcours utilisateurs ;
* la homepage / page d’accueil ;
* les pages de listing ;
* les pages de détail ;
* les mécanismes de recherche et de filtrage ;
* la manière dont les contenus sont catégorisés ;
* les données disponibles permettant d'identifier :

  * les contenus gratuits ;
  * les contenus récents ;
  * les contenus populaires ;
  * les contenus recommandés ;
  * les nouveautés ;
* les composants UI réutilisables ;
* le design system existant ;
* les contraintes techniques qui pourraient influencer l’UX.

Ne modifie pas immédiatement le code.

Commence par me restituer un **diagnostic synthétique** de l’UX actuelle.

---

# Étape 2 — Identifier les opportunités

À partir de ton audit, identifie les éléments qui devraient être davantage mis en avant.

Réfléchis notamment à la possibilité d’introduire ou d’améliorer :

### 1. Corrigés en libre accès

Créer une vraie mise en avant des corrigés gratuits.

Exemples de pistes :

* badge "Gratuit" clairement identifiable ;
* section dédiée "Corrigés gratuits" ;
* CTA permettant d’accéder directement au corrigé ;
* différenciation visuelle entre contenu gratuit et contenu nécessitant une action ;
* filtres permettant d’afficher uniquement les contenus accessibles gratuitement.

L’objectif est que l’utilisateur puisse comprendre **en quelques secondes où trouver de la valeur gratuitement**.

### 2. Ajouts récents

Créer un véritable espace de découvrabilité des nouveautés.

Exemples :

* section "Nouveautés" ;
* badge "Nouveau" ;
* tri par date ;
* "Ajouté récemment" ;
* mise en avant temporaire des nouveaux contenus ;
* éventuellement une logique de fraîcheur pour éviter qu’un contenu reste éternellement marqué comme nouveau.

### 3. Contenus populaires / pertinents

Évalue la pertinence de mettre en avant :

* les contenus les plus consultés ;
* les corrigés les plus recherchés ;
* les contenus populaires par matière / catégorie ;
* les contenus recommandés ;
* les contenus similaires ;
* les tendances du moment.

Ne mets ces éléments en place que si les données nécessaires existent réellement.

### 4. Découverte

Réfléchis à la manière d’aider un utilisateur qui arrive sur l’application et se demande :

> "Qu’est-ce que je peux faire ici ?"

L’interface doit idéalement permettre de comprendre immédiatement :

1. ce qui est disponible ;
2. ce qui est nouveau ;
3. ce qui est gratuit ;
4. ce qui est populaire ;
5. comment trouver rapidement ce dont j’ai besoin.

---

# Étape 3 — Fais tes propres suggestions

Ne te limite surtout pas aux exemples que je viens de donner.

Je veux que tu identifies **des idées UX potentiellement gagnantes**.

Par exemple, réfléchis à :

* une meilleure homepage ;
* une navigation plus intuitive ;
* des raccourcis vers les contenus importants ;
* une personnalisation légère ;
* des recommandations contextuelles ;
* des filtres intelligents ;
* une meilleure recherche ;
* des états "Nouveau", "Gratuit", "Populaire", etc. ;
* des collections éditorialisées ;
* des parcours spécifiques pour les nouveaux utilisateurs ;
* la mise en avant des contenus récemment consultés ;
* la continuité de navigation ;
* la réduction du nombre de clics pour atteindre un corrigé ;
* la mise en valeur des contenus à forte valeur pédagogique.

Pour chaque suggestion, explique brièvement :

* **le problème utilisateur résolu** ;
* **la valeur apportée** ;
* **l’emplacement UX recommandé** ;
* **la complexité d’implémentation** : faible / moyenne / élevée ;
* **l’impact potentiel** : faible / moyen / élevé.

---

# Étape 4 — Proposer une nouvelle hiérarchie UX

À partir de ton analyse, propose une hiérarchie claire de l'information.

Par exemple, sur la page d’accueil, évalue une structure du type :

1. Hero / proposition de valeur
2. Recherche principale
3. Accès rapides
4. Corrigés gratuits
5. Nouveautés
6. Contenus populaires
7. Parcours par catégorie
8. Recommandations
9. Autres contenus

Mais **ne pars pas du principe que cette structure est la bonne**.

Propose celle qui te semble la plus pertinente après analyse du projet.

---

# Étape 5 — Priorisation

Construis une roadmap UX avec trois niveaux :

### 🔥 Quick wins

Modifications à fort impact et faible complexité.

### 🚀 Priorité

Améliorations importantes nécessitant un peu plus de travail.

### 💡 Expérimentations

Idées intéressantes à tester mais dont l’impact doit être validé.

Pour chaque proposition, donne :

| Proposition | Impact | Effort | Priorité | Justification |
| ----------- | ------ | ------ | -------- | ------------- |

---

# Étape 6 — Implémentation

Après avoir présenté ton diagnostic et tes recommandations, **passe à l’implémentation des améliorations que tu juges les plus pertinentes**.

Contraintes importantes :

* respecte le design system existant ;
* réutilise les composants existants lorsque c’est pertinent ;
* évite les duplications ;
* ne casse pas les fonctionnalités existantes ;
* privilégie une UX responsive ;
* pense mobile-first ;
* respecte l’accessibilité ;
* évite les animations inutiles ;
* garde une interface visuellement sobre et professionnelle ;
* ne surcharge pas la page avec trop de sections ;
* privilégie la hiérarchie visuelle plutôt que l’accumulation de composants.

Si une information nécessaire n’existe pas dans le backend, **ne simule pas une donnée réelle sans me le signaler**.

Dans ce cas, indique clairement ce qui serait nécessaire côté données/API.

---

# Principes UX à respecter

Je veux une interface :

* **claire** ;
* **moderne** ;
* **rapide à comprendre** ;
* **orientée découverte** ;
* **mobile-first** ;
* **accessible** ;
* **visuellement hiérarchisée** ;
* **sans surcharge cognitive**.

La règle principale :

> L’utilisateur doit pouvoir identifier très rapidement ce qui est nouveau, ce qui est gratuit et ce qui est pertinent pour lui.

Mais attention :

**"Mettre en avant" ne signifie pas "mettre partout".**

Évite les badges, couleurs, CTA et sections excessifs qui finiraient par rendre l’interface bruyante.

---

# Critères de réussite

À la fin, je veux obtenir :

1. un audit UX de l’existant ;
2. une liste d’opportunités ;
3. tes propres suggestions UX ;
4. une proposition de nouvelle hiérarchie de l’information ;
5. une priorisation Impact / Effort ;
6. l’implémentation des améliorations prioritaires ;
7. un résumé des fichiers modifiés ;
8. les éventuelles évolutions backend/API nécessaires ;
9. les points qui mériteraient d’être testés auprès des utilisateurs.

## Important

Ne te contente pas d’exécuter littéralement ma demande.

**Challenge mes hypothèses.**

Si tu identifies une meilleure façon de mettre en valeur les corrigés gratuits, les nouveautés ou les autres contenus importants, propose-la.

Je cherche une amélioration **réellement gagnante en termes d’UX et de découvrabilité**, pas simplement une refonte esthétique.
